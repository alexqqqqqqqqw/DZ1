# Библиотека промптов

Каждый шаблон собран как Role, Task, Context, Format. Пример подставлен на задачу «Нормы».

## 1. Генерация компонента

```markdown
Role: Ты frontend-разработчик на TypeScript и React. Верстаешь экран мобильного сервиса еды.
Task: Сделай карточку набора рациона.
Context: На входе название, длительность 1 или 7, цена в копейках, калории и число приёмов пищи. Рядом ссылка на меню. Пустого названия не бывает. Цена недели приходит готовой, умножать дневную цену запрещено.
Format: Один файл компонента без `any`. Состояния загрузки в этот компонент не входят. Кнопка ведёт по href. Текст интерфейса на русском.
```

Пример использования: карточка `PlanCard` в `src/components/states.tsx`. На входе `priceKopecks={549000}`, на экране «5 490 ₽» и ссылка «Смотреть меню».

## 2. Рефакторинг

```markdown
Role: Ты ревьюер, который оставляет поведение и убирает скрытые правила из JSX.
Task: Вынеси проверку даты доставки из компонента в чистую функцию.
Context: Дата считается календарным днём Europe/Moscow плюс 2 дня, не 48 часами. Функция нужна и форме, и API.
Format: Функция с аргументом `now`, тесты на вечер UTC, который в Москве уже следующий день, и на отказ завтрашней даты. Компонент только показывает `min` и текст ошибки.
```

Пример использования: `earliestDeliveryDate` и `isDeliveryDateAllowed` в `src/lib/domain.ts`, поле `DeliveryDateField`.

## 3. Тесты

```markdown
Role: Ты инженер, который пишет проверки до правки продакшена.
Task: Покрой создание заказа, чужой доступ и оплату.
Context: База `norma_test`, роль без обхода RLS. Успешная карта 4242424242424242, отказ банка 4000000000000002. Цена недели в заказе 549000 копеек.
Format: Один файл Vitest. Проверки: дата 2020 года даёт 400, чужой пользователь получает 403, отказ карты даёт 402 и статус payment_failed, в payments нет столбцов number, pan, cvv.
```

Пример использования: `src/server/orders.integration.test.ts`.

## 4. Ошибка и баг

```markdown
Role: Ты дежурный по инциденту. Сначала называешь наблюдаемый симптом, потом место в коде.
Task: Найди, почему SELECT заказов без пользователя возвращает строки.
Context: Роль norma_app, на orders включён и форсирован row level security. Политика сравнивает user_id с app.user_id. Запрос идёт вне транзакции с set_config.
Format: Коротко: какой запрос, какой ожидаемый count, какой патч. Без отключения RLS.
```

Пример использования: `withUser` в `src/server/db.ts` вызывает `set_config('app.user_id', ..., true)` внутри транзакции. Тест ждёт count 0 без этого вызова.

## 5. Декомпозиция

```markdown
Role: Ты тимлид. Режешь сценарий оформления на независимые куски.
Task: Разложи оформление заказа на шаги, которые можно сделать по очереди.
Context: Нужны дата, адрес, сессия, оплата. Конструктора блюд нет. Город только Москва.
Format: Нумерованный список из трёх или больше шагов. У каждого шага вход, выход и что считается готовым. Без оценки сроков в днях.
```

Пример использования: цепочка в `prompt_methodology.md`: правила домена, контракт API, состояния экрана.
